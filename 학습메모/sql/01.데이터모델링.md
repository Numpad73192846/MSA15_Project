## SQL이란?
SQL은?
뜻: Structured Query Language(구조화 질의어)
해석: 정해진 규칙에 따라 데이터를 처리하는 언어

## 데이터 모델링
데이터 모델링시 유의할 사항 3가지
1. 중복(Duplication)
 : 데이터베이스가 여러 장소에 같은 정보를 저장하지 않게 한다.
2. 비일관성(Inconsistency)
 : 데이터 모델을 어떻게 설계했느냐에 따라 사소한 업무변화에도 데이터 모델이 수시로 변경되어 어려움을 가중시킬 수 있다.
3. 비효율성(Inefficiency)
 : 데이터 중복이 없더라도 비일관성은 발생할 수 있다. 데이터 모델링을 할 때 데이터와 데이터 간의 상호 연관 관계에 대해서 명확하게 정리해야한다.

## 데이터베이스 스키마 구조 3단계
1. 외부스키마(External Schema)
 : 사용자 관점의 스키마
2. 개념스키마(Conceptual Schema)
 : 조직 전체의 데이터 구조를 기술한 스키마
3. 내부스키마(Internal Schema)
 : 물리적인 저장장치의 관점의 스키마

## 관계의 표기법
1. 관계명
 : 관계를 나타내는 동사형 이름
 : 참여하는 엔터티에 따라 능동형 혹은 수동형으로 명명됨.
 : 모든 관계는 두 개의 관계명을 가진다.(예: 사원 → 소속된다 → 부서 → 포함한다 → 사원)
2. 관계차수
 : 두 엔터티 간에 얼마나 많은 인스턴스가 참여하는지를 나타낸다.
 : 1:1, 1:N, M:N(일대일, 일대다, 다대다)
3. 선택성(선택사양)
 : 관계가 반드시 맺어져야 하는지(필수), 아니면 없어도 되는지(선택)를 나타냄
 : 필수: 관계가 반드시 존재해야 함(세로선 | 표기)
 : 선택: 관계까 없을 수도 있음(동그라미 O 표기)

## 데이터 독립성(Data Independence)
1. 데이터 독립성이란?
 : 하위 단계의 구조가 바뀌어도 상위 단계의 서비스는 영향을 받지 않는 성질

2. 왜 필요한가?
 2-1. 유지비용 감소: 데이터 구조를 바꿔도 앱을 다시 개발할 필요가 없음
 2-2. 데이터 복잡도 감소: 사용자는 데이터가 실제로 하드디스크 어디에 저장되는지 몰라도 됨
 2-3. 중복성 제거: 여러사람이 같은 데이터를 각자 관점에서 자유롭게 쓸 수 있음

3. 논리적 독립성(Logical Independence)
 : 개념 스키마가 변경되어도 외부 스키마는 영향을 받지않는 성질을 말함
 : TEST= "테이블 구조가 바뀌거나(컬럼 추가 등) 속성이 변경되어도 사용자가 보는 화면(View)이나 응용 프로그램은 그대로 유지될 수 있는가?"
4. 물리적 독립성(Physical Independence)
 : 내부 스키마가 변경되어도 개념 스키마는 영향을 받지 않는 성질
 : TEST= "데이터베이스의 저장 장치를 교체하거나, 성능 향상을 위해 인덱스(Index)를 새로 만들어도 전체적인 논리 구조(테이블 구조)는 변하지 않는가?

## 식별자의 종류
1. 주식별자(Primary Identifier)
 : 설명: 엔터티 내에서 각 인스턴스를 유일하게 구분하는 대표 식별자
 : 특징: 유일성, 최소성, 불변성, 존재을 모두 만족해야함.
  (없으면 안되고, 중복되면 안되고, 변하면 안되고, 하나는 반드시 있어야함)
2. 외부식별자(Foreign Identifier)
 : 설명: 다른 엔터티와 관계를 통해 가져온 식별자
 : 특징: 자기 자신의 식별자가 아니라, 타 엔터티의 주식별자를 참조함.(물리적 DB의 FK)  
3. 단일식별자(Single Identifier)
 : 설명: 하나의 속성으로만 구성된 식별자
 : 예시: 사번, 학번, 주민등록번호
4. 복합식별자(Composite Identifier)
 : 설명: 두 개 이상의 속성이 합쳐져야만 유일성이 확보되는 식별자
 : 예시: 학번 + 과목코드(수강신청 엔터티 등)
5. 인조식별자(Artificial Identifier)
 : 설명: 원래 업무상 존재하지 않지만, 관리를 위해 인위적으로 만든 식별자.
 : 예시: 주문번호, 일련번호(주로 복합식별자가 너무 복잡해 단순화하기 위해 만듦)
6. 자연식별자(Natural Identifier)
 : 설명: 비즈니스 업무 프로세스에서 자연스럽게 발생하는 식별자
 : 예시: 주민번호, 사업자번호, 사번
분류 기준,종류,비고
대표성 여부,주식별자 vs 보조식별자,보조는 유일성은 있지만 대표는 아님
생성 방식,자연식별자 vs 인조식별자,원래 있던 것 vs 억지로 만든 것
속성 수,단일식별자 vs 복합식별자,속성이 1개 vs 2개 이상
대체 여부,원조식별자 vs 대리식별자,인조식별자와 비슷한 개념
