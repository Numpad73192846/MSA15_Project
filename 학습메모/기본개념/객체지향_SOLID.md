## JAVA의 5대 핵심요소: SOLID 원칙
1. S: Single Responsibility Principle (단일 책임 원칙)
 - 클래스 한개는 하나의 책임만 가져야 한다.
2. O: Open/Closed Principle (개방-폐쇄 원칙)
 - 확장에는 열리고, 수정에는 닫혀야 한다.
3. L: Liskov Substitution Principle (리스코프 치환 원칙)
 - 자식 클래스는 언제나 부모 클래스로 교체할 수 있어야 한다.
4. I: Interface Segregation Principle (인터페이스 분리 원칙)
 - 특정 클라이언트를 위한 인터페이스 분리.
5. D: Dependency Inversion Principle (의존성 역전 원칙)
 - 구체적인 클래스보다 추상화(인터페이스)에 의존해야 한다.

### JAVA의 객체 지향
1. 객체는 데이터(속성)와 데이터를 다루는 행동(메서드)을 하나로 묶은 개념.
현실세계의 사물이나 개념을 프로그램으로 표현.
예: '자동차'객체면:
- 데이터: 색상, 속도, 연료량, 모델명 등
- 행동: 가속, 감속, 방향전환, 주유 등

2. 예시코드
class car {
    // 데이터
    String color;
    int speed;
    int fuel;
    String model;
    // 행동
    void accelerate() {
        speed += 10;
        fuel -= 1;
    }
    void brake() {
        speed -= 10;
    }
}
// 위 코드를 보면 데이터와 행동(메서드)가 `car` 클래스 안에 묶여있음.
// 쉽게 생각하면 데이터와 행동은 함께 다녀야함.

3. 그렇다면 JAVA는 왜 객체를 지향하는가?
    1. 직관성: 컴퓨터의 언어를 현실세계에서 자연스럽게 모델링해서 인간이 생각하는 방식 그대로 코드로 작성하기 위해서.
    2. 복잡성: 프로그램을 작은 단위(객체)로 나눠 각각을 독립적으로 이해하고 관리하면 
    3. 재사용성: 한번 만든 객체(클래스)를 여러 곳에서 재사용 할 수 있다
    4. 유지보수 용이성: 자동차의 브레이크 로직을 바꾸고싶다면 클래스의 brake()메서드만 수정하면됨.
    5. 정보은닉(캡슐): 객체(클래스)내부의 복잡한 구현을 숨기고 필요한 기능만을 외부에 제공. 운전하는 사람은 엑셀, 브레이크, 핸들만 알면 왠만하면 됨.
